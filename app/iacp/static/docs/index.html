Crea y administra instancias mediante perfiles autorizados. Sigue cada solicitud hasta su resultado y conserva el control de su ciclo de vida.

Dos credenciales, dos alcances. HTTP Basic permite leer esta documentación. Para llamar a la API, pulsa Authorize e introduce solo el token Bearer del tenant, sin el prefijo. La clave de documentación no autoriza llamadas a /v1. La autorización no se conserva al recargar.
  1. Consulta perfiles. Selecciona un perfil disponible y una política vigente aprobada; no envíes IDs de infraestructura interna.
  2. Crea una intención. Envía POST /v1/instances con una Idempotency-Key nueva y conserva instance_id, operation_id y job_id.
  3. Sigue su estado. Un 202 confirma admisión. Consulta la misma operación hasta completed, failed o uncertain. Con start_on_create, comprueba también fulfillment y los datos de acceso.
  4. Administra Lifecycle. Utiliza start, reboot y shutdown sobre el UUID propio. Running no garantiza SSH, Cloud-Init ni disponibilidad de una aplicación.
  5. Elimina con autorización. Apaga ordenadamente y solicita DELETE bajo la política vigente. Espera el resultado terminal; no interpretes 202 como eliminación completada.

Reintentos: misma intención, misma clave y mismo cuerpo. Un cuerpo distinto con la misma clave devuelve 409. Ante uncertain, conserva el UUID y usa la reconciliación autorizada; no crees una instancia sustituta.

Los códigos aplicables se indican en cada operación. Conserva X-Request-ID para soporte; la lista de instancias devuelve X-Total-Count. Los ejemplos son sintéticos: sustituye las referencias por recursos autorizados.
