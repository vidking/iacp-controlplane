Arquitectura y autenticación

El CRM consume la URL oficial https://iac.cyberfuel.com por HTTPS. Usa un token Bearer asociado al tenant; HTTP Basic solo protege esta documentación. La API valida el tenant y los perfiles autorizados, mientras los workers ejecutan las operaciones fuera de la petición.

Consulta GET /v1/profiles para conocer las políticas de autoservicio disponibles. No envíes VMID, nodo, state ni credenciales de infraestructura.

Flujo CRM → instancia

Dos credenciales, dos alcances. HTTP Basic permite leer esta documentación. Para llamar a la API, pulsa Authorize e introduce solo el token Bearer del tenant, sin el prefijo. La clave de documentación no autoriza llamadas a /v1. La autorización no se conserva al recargar.
  1. Consulta perfiles. Selecciona un perfil vigente.
  2. Crea una intención. Usa POST /v1/instances con una Idempotency-Key única. HTTP 202 significa admitida, no lista.
  3. Sigue el trabajo. Conserva instance_id, operation_id y job_id; consulta las operaciones hasta completed, failed o uncertain.
  4. Verifica red y acceso. Una VM creada o arrancada no garantiza DHCP, SSH ni disponibilidad de aplicación; comprueba el estado de red y el acceso autorizado.
  5. Administra Lifecycle. Usa start, reboot y shutdown sobre el UUID propio.
  6. Elimina. Solicita DELETE autorizado y espera el estado terminal.
curl -sS -X POST https://iac.cyberfuel.com/v1/instances \
  -H 'Authorization: Bearer TOKEN_DEL_TENANT' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: CRM-INTENCION-001' \
  -d '{"name":"crm-demo","profile_id":"44444444-4444-4444-8444-444444444444","start_on_create":true}'

Reintentos: misma intención, misma clave y mismo cuerpo. Un cuerpo distinto con la misma clave devuelve 409. Ante uncertain, conserva el UUID y usa la reconciliación autorizada; no crees una instancia sustituta.

Errores y reintentos

401 indica identidad ausente o expirada; 403, permiso insuficiente; 409, conflicto, cuota o clave idempotente reutilizada con otro cuerpo; 429, límite temporal; y 503, admisión o dependencia no disponible. Reintenta solo con la misma intención, clave y cuerpo. Ante uncertain, conserva el UUID y solicita reconciliación autorizada.

Componentes y colas

FastAPI valida y registra la intención en PostgreSQL. Redis/Celery entrega trabajos; el IaC Worker ejecuta planes autorizados y el Lifecycle Worker procesa energía. Cada cola y worker tiene una responsabilidad separada; no se deben publicar tareas manuales desde Desarrollo.

Estados y reconciliación

EstadoInterpretación
pending/runningTrabajo admitido o en ejecución.
completedResultado terminal confirmado.
failedResultado terminal con error; conserva eventos.
uncertainNo repetir automáticamente; observar backend y reconciliar con autorización.

Usa operation_id, job_id, instance_id, X-Request-ID y timestamps para trazabilidad. Fallos recuperables se reintentan mediante la misma intención; locks anómalos, colas detenidas o discrepancias de state no se fuerzan.

Qué hacer y cuándo escalar

Ante una operación fallida, conserva la respuesta y evidencia, no crees un sustituto y no borres state. Escala a Infraestructura si existe uncertain, operación no terminal, lock persistente, error repetido de PostgreSQL/Redis, divergencia con Proxmox o worker sin respuesta.

Release y comprobaciones

Una release identifica commit, imágenes por digest, esquema, configuración y evidencias. El runtime actual usa 0011_crm_contract; las migraciones históricas no describen el estado vigente.

Promoción y verify

  1. Comprobar SHA ejecutado, salud, imágenes, colas, locks y operaciones no terminales.
  2. Usar iacpctl y go_live.py con manifiesto revisado, respaldo y evidencia privada nueva. El flujo incluye inventory, preflight, promote y verify.
  3. Después comprobar readiness, workers, PostgreSQL, Redis, Traefik, OpenAPI y autenticación.

Rollback seguro

El rollback cierra admisión y conserva PostgreSQL, Redis, state, historial y trabajos activos. No usa down -v, no borra estados ni fuerza desbloqueos. Una operación incierta sigue su procedimiento de recuperación y requiere Infraestructura.
