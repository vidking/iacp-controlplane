GUÍAS DE USO

Referencia técnica completa

La experiencia visual explica el contrato real sin convertir la trazabilidad comercial en un requisito operativo.

Contrato estable v1

Consulta GET /v1/plans y GET /v1/images. Crea con POST /v1/instances, usando plan_id e image_id. El consumidor no envía nodo, vCPU, memoria ni disco: esos valores vienen del catálogo certificado.

Base URL actual: https://dev-iac.cyberfuel.com
POST /v1/instances
Idempotency-Key: alta-ORD-1001
Authorization: Bearer <token>
Cómo consumir la API

En desarrollo la base es https://dev-iac.cyberfuel.com; al promover el mismo contrato la base será https://iac.cyberfuel.com. La versión, rutas y cuerpos permanecen en /v1.

# 1) catálogo
curl -H "Authorization: Bearer <TOKEN>" BASE/v1/plans
curl -H "Authorization: Bearer <TOKEN>" BASE/v1/images
curl -H "Authorization: Bearer <TOKEN>" BASE/v1/network-profiles

# 2) crear y seguir
curl -X POST BASE/v1/instances -H "Authorization: Bearer <TOKEN>" \
  -H "Idempotency-Key: alta-ORD-1001" -H "Content-Type: application/json" \
  --data @create-instance.json
curl -H "Authorization: Bearer <TOKEN>" BASE/v1/operations/<operation_id>
Comandos de lifecycle y eliminación

ready significa aprovisionada y encendida; stopped significa aprovisionada pero apagada. Ambas conservan la misma identidad y pueden gestionarse con lifecycle. El destroy es asíncrono y siempre debe seguirse por su operation_id; los fallos sin VM física también pueden limpiarse de forma lógica y auditable.

curl -X POST BASE/v1/instances/<instance_id>/power/start
curl -X POST BASE/v1/instances/<instance_id>/power/shutdown
curl -X POST BASE/v1/instances/<instance_id>/power/reboot
curl -X DELETE BASE/v1/instances/<instance_id>
Catálogo de planes, imágenes y red

Consulta GET /v1/plans, GET /v1/images y GET /v1/network-profiles para conocer las opciones certificadas. Elige un plan_id, un image_id y un network_profile; la API conserva los valores técnicos y no requiere que el consumidor conozca la infraestructura interna.

lab_dhcp es el perfil de laboratorio. prod_static asigna una IP libre del prefijo `/24` autorizado en NetBox, reserva x.x.x.1 como gateway y no acepta que el consumidor envíe una IP arbitraria. Permanece deshabilitado hasta completar la configuración del IPAM.

Las imágenes base son inmutables. customer_tag, cuando existe, se conserva como metadata de trazabilidad.

curl -H "Authorization: Bearer <TOKEN>" BASE/v1/plans
curl -H "Authorization: Bearer <TOKEN>" BASE/v1/images
curl -H "Authorization: Bearer <TOKEN>" BASE/v1/network-profiles
Acceso, contraseña y SSH

La consola pide contraseña para el usuario inicial root y replica el flujo operativo de referencia. La API también acepta SSH-only para automatizaciones. La contraseña se transporta mediante un secreto temporal y se elimina al terminar el aprovisionamiento.

Ubuntu y AlmaLinux usan root; el portal nunca muestra la contraseña después del envío.

Operaciones y diagnóstico

Estados públicos: queued, running, completed, failed y uncertain. Cada mutación devuelve un operation_id para consultar el progreso y los eventos.

Los eventos salen más recientes primero; para reconstruir una ejecución completa usa /v1/events?operation_id=<id>&sort=asc. uncertain requiere reconciliación física y no se interpreta como éxito ni como fallo seguro.

GET /v1/observability también devuelve max_concurrent, active_operations, queue_depth y el estado actual de cada worker. La consola puede refrescar esta vista mientras haya operaciones en curso.

GET BASE/v1/operations/<operation_id>
GET BASE/v1/events?operation_id=<operation_id>&sort=asc
GET BASE/v1/observability
GET BASE/v1/instances/<instance_id>
GET BASE/v1/instances/<instance_id>/network
GET BASE/v1/instances/<instance_id>/power
Lifecycle y eliminación

Una instancia aprovisionada puede iniciarse, apagarse o reiniciarse mediante operaciones asíncronas. Antes de eliminarla, confirma que su energía sea stopped; luego espera la operación de destroy y verifica que su estado sea deleted.

POST BASE/v1/instances/<instance_id>/power/start
POST BASE/v1/instances/<instance_id>/power/shutdown
POST BASE/v1/instances/<instance_id>/power/reboot
DELETE BASE/v1/instances/<instance_id>
Trazabilidad avanzada de API

customer_id, customer_tag, order_id y product_id son metadata opcional y completa. No conceden permisos, no cambian el plan y no seleccionan nodo.
